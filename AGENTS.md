# Repository instructions for coding agents

These instructions apply to all future work in this repository.

## Releases from main

Whenever work includes preparing, tagging, publishing, or documenting a user-facing release from `main`, read and follow `docs/RELEASE_NOTES_TEMPLATE.md`.

Every GitHub Release page must use the detailed Friends to Amigos product-update format defined there. In particular:

- do not publish only autogenerated commit notes;
- include a clear version title and release summary;
- include download/install guidance when an APK is attached;
- include a detailed `New in vX.Y.Z` section grouped by relevant product areas;
- include specific bug fixes and user-visible technical improvements;
- include recent previous-release highlights when useful;
- include known issues/limitations when relevant;
- derive every claim from the actual code/content shipped from `main`;
- ensure the release notes describe the same commit/build as the attached APK.

Treat this release-note requirement as part of release completion, alongside tests and the Android build. A release task is not complete until its GitHub Release notes are ready in this format.
