# Public showcase visual release checklist

Complete this for **every published image**, not only Profile. Store the results in the release report and bind it to the manifest version/fingerprint.

- [ ] Actual current UI/version; generation commit or null is truthful, fingerprint matches final UI inputs.
- [ ] All visible tabs read Home · Learn · Practice · Review · Profile in order; correct active tab, no internal Games label leaked.
- [ ] Useful representative screen and coherent illustrative data; no invented learner achievement or assessment capability.
- [ ] No card, text, primary control or modal accidentally clipped or obscured.
- [ ] No horizontal overflow or content exposed under/below the fixed app navigation.
- [ ] No fake Samsung/Android bars, artificial system-navigation gap or misleading device claim.
- [ ] Normal readable text and correct released colours/theme; fonts/animations settled.
- [ ] Sensible top/card boundary or documented question/feedback scroll anchor.
- [ ] Keyboard absent unless explicitly the subject (keyboard stress shots normally stay outside the showcase).
- [ ] Dictionary popup fits; opening it has not selected/submitted an answer.
- [ ] Image is genuinely useful to a repository visitor and matches its caption.

For retained images also record the unchanged UI fingerprint, version reviewed and specific retention reason. For a regenerated but byte-identical image record the new actual capture; do not force cosmetic pixel changes.

Report the screenshot count, source profiles, all filenames with full PNG SHA-256 hashes, automated validation, manual reviewer/date, source fingerprint marker and known limitations. Browser simulation is not physical-device validation. Native build/unit/lint success is not acoustic or native-speaker review.
